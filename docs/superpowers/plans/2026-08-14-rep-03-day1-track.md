# Rep Phase 3 — Day 1 becomes a self-paced track

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Retire the 135-minute instructor-led Zillow Preferred Day 1 and replace it with eleven
self-paced modules totalling ~75 minutes, plus a 45-minute live debrief — with the same learning
objectives, proved by work rather than by attendance.

**Architecture:** Almost no new engineering. Phase 1 gives the shelf, the track, assignment and
certificates; Phase 2 gives the screenshot practice CRM, the `sim` card and its gate. This phase is
**authoring**: eleven module documents in the existing `db/rep_curriculum.mjs` shape, four scenario
documents in the Phase 2 shape, and a track assembly script. Budget it as writing hours, not
engineering hours — that is the honest read, and pretending otherwise is how this stalls.

**Tech Stack:** Node data-push scripts against PostgREST with the service role (the `db/rep_curriculum.mjs`
pattern), JSON scenario documents, the existing card types.

**Spec:** `docs/superpowers/specs/2026-08-14-rep-training-library-design.md` (§5)

**Depends on:** `plans/2026-08-14-rep-01-library-shelf.md` (all tasks),
`plans/2026-08-14-rep-02-practice-crm.md` (all tasks, and its Task 10 pivot gate answered *yes*).

## Global Constraints

- **The source of truth is frozen.** All content comes from
  `~/Documents/Codex/2026-08-08/zillow-preferred-day-one-framework/work/production/`:
  `day1-slide-script.md` (940 lines, 36 slides), `day1-scenario-pack.md` (340 lines),
  `day1-homework-handout.md`. **Transcribe and adapt; do not invent new facts, numbers, stages or
  scripts.** If a module needs something the script doesn't say, that's a question for Eric, not a
  gap to fill.
- **Every number keeps its source line.** `stat` cards carry `src`. The three Zillow standards
  (25% pickup, 4% PCVR, 10% pre-approval) are already stated in `db/rep_curriculum.mjs` module M0 —
  use that wording verbatim so the two never drift.
- **Do not ship Z3 twice.** Slides 11–12 duplicate the existing *Welcome to Preferred* module (M0,
  `a0000000-0000-0000-0000-000000000000`). Z3 **is** M0, re-tagged into the track — not a new module.
- **No module ships whose only proof is four multiple-choice questions** (spec §5.3).
- **Screenshot provenance is binding** — see Phase 2's constraints. `LIVE DEMO` and `RECAPTURE`
  material stays in the live debrief until an approved current-team capture exists.
- **Six to ten minutes per module, one objective each.** A module that needs two objectives is two
  modules.
- Commit per task. Fetch and merge `main` before every push.

### Task 9: Pilot on one new hire, then retire the lecture

- [ ] **Step 1: Assign, and get out of the way**

Assign the track to exactly one incoming agent with a due date. Send no supplementary explanation —
what they can't do alone is the finding.

- [ ] **Step 2: Measure**

```sql
select m.title,
       min(p.updated_at) as started, max(p.passed_at) as passed,
       max(p.attempts) as attempts, max(p.score) as score
  from rep_progress p join rep_modules m on m.id = p.module_id
 where p.learner_id = '<learner>' group by m.title order by min(p.updated_at);

select s.slug, a.score, a.passed, jsonb_array_length(a.events) as evts, a.started_at
  from rep_sim_attempts a join rep_scenarios s on s.id = a.scenario_id
 where a.learner_id = '<learner>' order by a.started_at;
```

Against a 135-minute baseline, the numbers that matter: **total elapsed time**, **attempts per
scenario**, and **which check failed most often**. A check that everyone fails is a teaching defect in
the module before it, not a hard learner.

Two questions: where did you get stuck, and where did you feel talked down to? Both produce edits.
